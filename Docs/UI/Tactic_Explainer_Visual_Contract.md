# Tactic Explainer Visual Contract

Stage 8.22B；工程实现与用户视觉验收分开。遵循 [Match Flow Visual Language](MatchFlow_Visual_Language_v1.md) 与 [Production Match Shell](Production_Match_Shell_Visual_Contract.md)。

## 入口与结构

部署操作条保留“战术说明”次按钮。打开居中的深蓝模态框，背景压暗；标题“战术说明”，副标题“查看战术用途、角色需求与详细规则”，右上 × 关闭。1440×880 的设计面板放在 1920×1080 逻辑画布中，使用现有比例适配思路。左导航固定：基础进攻（远射、内切、传中、直塞），定位球（角球、近距离任意球、远距离任意球、点球）。PassControl 不出现。

右栏依次呈现标题、用途、路线／方法、记忆句、“角色与关键属性”攻防卡、“相关特性”、基础进攻技能范围提示、次级“查看计算方式”。直塞还列出成功后的两种单刀方法，文案明确后续关系，不将其伪装成路线骰结果。

## 表现语义

- 复用 Match Shell 的 navy、细边框、mint、冷白／灰蓝及 Noto Sans SC 字体；不改变玩家身份色。
- 记忆句只强调属性词和“取较高值”，一般叙述保持中性。角色标签与属性列分开；近任意球／点球同时显示射门、传球与取较高值。
- 门将实际提供属性时才出现；可选激活项标“门将（参与时）”。自动参与门将保留正常标签；单刀的基础项与激活额外项在计算卡分别列出。
- 特性 chip 只通过 stable Trait ID 读取 `FPlayerTraitFormula::DisplayName`；无图标、等级、数值或当前球员所有权。随路线切换，纯程序方法不填充无关特性。
- 不显示“各角色的参与条件见详细规则”。技能范围提示明确仅指基础进攻，避免误称定位球也依赖技能范围。
- 计算方式替换同一右栏内容，提供“返回概览”；仅右栏滚动，模态框和导航不改变大小。不会产生嵌套窗口。
- 使用紧凑文字导航，不新增图标资产库。参考图的层级、攻防卡和条目分组保持一致。

## 只读边界与来源

`FMCodexTacticExplainerCatalog` 为静态教育目录，不读取 Match State、玩家快照、隐藏 View 或 RNG，不计算当前比赛值／胜负。基础进攻与角球公式项复用 `FTacticalRuleDescriptionCatalog`；定位球说明依照当前 resolver 与 [Formula contract](../Rules/Rules_Simplification_Formula_Contract.md) 和 [Trait contract](../Rules/Trait_System_Design_Contract.md)。具体公式以这些来源为准，此文不复制公式表。

选择战术／路线仅改变 reference state。遮罩截获底层鼠标，Screen 公共提交边界在面板打开时拒绝比赛动作；关闭恢复原部署上下文。阶段离开部署则关闭。Local/Network 共享同一 Screen 和模态框。原战术卡 hover 的非模态紧凑说明保持原用途。

本合同替代 Tactical Information v1 中旧“部署 Reference 水平选择器／关闭战术说明按钮／同一 hover 面板”的表现规定，其余 hover、authority 与 legality 合同继续有效。Guided Lesson 1 保持原有禁止打开此入口的行为，不作教学适配。

## 计算方式

此层只回答“这个战术具体怎么算”，保留已验收的概览、模态框、导航和路线 pills。入口为次级“查看计算方式”，右栏标题为“计算方式”，所选战术／方法仍可见，同栏“返回概览”。

普通公式使用可选“前置判定”、并列进攻／防守卡和一句结果：“比较双方最终值，数值较高的一方获胜。”每个操作数占语义明确的一行，角色与属性分开；属性使用 mint，系数／运算符更安静。保留 ×1／×0.5、带来源的固定攻防修正、门将项及“（参与时）”。近任意球／点球以“主罚能力 · 射门 与 传球 取较高值”表达最大值，随后列进攻骰点。角球自身的人数修正保留简短说明，不混同运动战通用修正。

公式用“进攻骰点／防守骰点”；纯程序方法用“投掷 1 次骰子／投掷 2 次骰子”，只列真实成功与失败条件，不制造攻防属性卡。反越位并列普通球员与反越位专家，分别一次／两次投掷，后者任意一次掷出 6 成功，两次均未出 6 则越位。

不在各方法重复 D6、通用特性触发／等级表、战术球员优势、体力／平局层级、掷骰生命周期或候选／实际参与者理论，不新建百科。上述机制仍照常生效，实际比赛 Formula disclosure 保持原合同；此静态核心计算视图不冒充当前比赛的最终数值。通用修正提示默认省略。主要计算页应在 1600×900 下直接读完，复杂页可仅在右栏滚动，不缩小字体强塞。

## 验证与验收

8.22B 原入口／公共意图隔离验证保留。本次微调只更新 `FMCodex.LocalPlay.TacticExplainer.ContentContract`、`NavigationAndDisclosure`，补充 `CalculationView.ProceduralMethods`，覆盖核心操作数／系数／修正／GK、移除文案、同栏往返与程序条件。默认预算为一次增量 Editor build、一次真实 Local PIE 同一会话检查 CutInside Direct、Cross Low、AntiOffside、Near FK Direct；1920×1080 只作同会话快速布局检查。未改 reflected schema，不专门请求 UHT。此次首轮传中／内切高度超出固定右栏，压缩空白后内切仍有 2.2 个逻辑像素余量超出；因此实际进行三次增量构建、两次四页 PIE 与一次仅内切布局补测。三个聚焦测试通过，最终复用已通过的页面／隔离证据并补齐内切布局，未扩大 gameplay 回归范围。

工程检查不替代 USER PIE：计算可读性、中文／自然骰子表达、门将与系数扫描、公式换行、特殊方法清晰度及商业一致性由用户验收。Guided Match 仍暂停；不改玩法、权威状态或 Network 边界。

## Stage 8.22C：计算标签防遮挡

“前置判定”和“结果”标签按文字实际 desired width 自动分配宽度，正文在标签后保留 14 个逻辑像素间距；移除旧的固定 96 宽容器，避免中文粗体末字与正文重叠。正文继续自动换行，不改变静态计算文案、数据来源、概览布局或导航。

最终 B-C 微调保持模态外壳、左导航和右栏 host 常驻；选中状态通过绑定更新，动态右栏在挂载前完整准备，并一次替换旧页。换行控件从第一帧使用现有固定模态的逻辑宽度，避免新建 SWrapBox 先按默认 100 宽排版、下一 Tick 才切换到实际宽度的跳变。战术／路线切换都回到顶部；换顶级战术从计算方式回到概览，路线切换沿用当前概览／计算方式模式。没有额外延迟或切换动画，说明状态仍不提交玩法意图。

## Stage 8.30E：普通部署上下文战术入口

本节替代普通运动战部署的旧模态入口规定；定位球及其他旧说明依赖保留，Guided Lesson 1 沿用既有入口限制。普通部署不显示大号“战术说明”按钮，结束部署右侧按 `远射 → 内切 → 传中 → 直塞` 显示零至四个次级信息 chip。它们来自进攻方公开、可用或已部署卡片的既有 Hand Micro／Pitch Mini TP 匹配列表，按稳定战术身份去重；不扫描全目录、不计算完整行动合法性，移动到球场不会丢失家族。

只有公开 TP 的结果窗口完全消失后才出现，复用手牌技能揭示门控。整体淡入 0.4 秒并向上归位 4 个逻辑像素，每个新 AttackSequence／公开 TP／进攻方上下文一次；hover、点击、刷新、同上下文重建和部署不重播，也不延迟输入。未公开 TP、特殊路线、离开部署、终场和重置均清除列表或选择。

chip 高 44，文字水平／垂直居中，左右各 16、上下 0 内边距，普通／hover／选中使用相同布局；使用深蓝底、细青色边线、mint 文字；hover 轻微提亮，选中状态加深底色和边线，不使用主按钮的实心亮色。结束部署保持原有 66 高主操作。点击打开中央球场内唯一的非模态详情，最大 880×800，以实际球场区域居中、底部内缩 8，四周至少留 8；不进入手牌栏、比分栏或操作条。桌面普通战术的概览／各分支计算页完整容纳，无需滚动；小视口保留实际溢出时的滚动回退。仅嵌入模式收紧空白：路线下方 20→12，概览记忆句／角色标题下方 12→8，计算标题下方 16→8、结果上方 16→12。保留原字号、文字与公式，不隐藏内容来消除滚动条。无压暗遮罩、不捕获焦点。再次点击关闭，换 chip 直接替换内容，Esc 仅在打开时消费，外部点击关闭后仍传递给原目标。
